# Learnings

- 2026-04-15: The support-matrix tests work well as a full-enum sweep that classifies each `CustomEntityBaseType` as supported, permanently excluded, absent on the version surface, or excluded by the advertised version-local contract. Comparing the full actual supported set back to the expected included set catches both underclaims and overclaims.
- 2026-04-15: For the current parity baseline, `1.13.2`, `1.16.5`, and `1.17.1` stay zombie-only while keeping `COW` as an explicit preserved exclusion; `1.19.2` can derive its advertised set from all present Bukkit entity types minus the permanent exclusions and its preserved `COW` exclusion.
- 2026-04-15: Sample-plugin scenario evidence stays descriptor-driven end-to-end; adding a field like `selectedBaseType` only reaches `assertions.json` when `EntityScenarioDescriptor` advertises it, and deterministic family scenarios can reuse the existing flows by selecting the first supported base type from a fixed priority list.
- 2026-04-15: `1.13.2` can safely widen its explicit allowlist from `ZOMBIE` to `ZOMBIE` plus `SKELETON` when support checks, metadata registration, and attach/replacement gating all share the same contract, while `COW` remains an explicit preserved exclusion and replacement-bridge tests cover skeleton prepare/allocate, lifecycle binding, and CraftBukkit handle rebinding.
- 2026-04-15: `1.16.5` now uses the same explicit support-contract shape as `1.13.2` for `supports()`, metadata registration, and attach/replacement preparation, but its final advertised set must remain `ZOMBIE`-only until goal-support parity expands beyond the version-local zombie executor.
- 2026-04-15: `1.17.1` can safely widen from `ZOMBIE`-only to an explicit `{ZOMBIE, SKELETON}` allowlist when `supports()`, metadata registration, and replacement preparation all share the same contract, `COW` stays an explicit preserved exclusion, and goal-attach tests prove skeleton snapshot/mutation parity alongside replacement attach coverage.
- 2026-04-15: `1.8.8` broad support can be hardened into one explicit allowlist derived from the real 1.8.8 Bukkit `EntityType` surface, with permanent exclusions kept explicit, metadata registration sourced from the same allowlist, replacement safety guarded before metadata lookup, and a direct factory test covering both the full support matrix and legacy `EntityTypes` mapping repair.
- 2026-04-15: `1.19.2` now centralizes its broad modern support behind one advertised support contract derived from the version-local Bukkit surface minus permanent exclusions and preserved `COW`; `supports()`, metadata registration, attach rejection, and replacement rejection all consume that same contract so the `COW` edge case stays explicit instead of implicit.
- 2026-04-15: `1.21.11` now uses the same explicit broad-support contract shape as the earlier parity tasks, but with no extra preserved exclusions beyond the permanent `{UNKNOWN, PLAYER, WEATHER, COMPLEX_PART}` set; the advertised support set remains the full present Bukkit-backed surface, metadata registration is sourced from that same set, and the 1.21.11 tests now pin representative hostile/passive/special-case families plus attach/spawn goal-provider acceptance.
- 2026-04-15: The shared runtime tests now pin the final per-version entity-support matrices separately from the profile-based runtime support declarations, while each `SpigotVersionAdapterV1_*Test` performs the same full-enum allowlist sweep used by the version-local factory tests so overclaims fail at both the shared gate and the adapter boundary.
- 2026-04-16: Task 10 evidence generation now persists representative scenario artifacts directly from the `test-plugin` integration suite under `test-plugin/target/entity-matrix/<selected-server>/<scenario>/`, and each trace embeds the deterministic candidate-version selection record so rejected or skipped family coverage is explicit instead of silent.
- 2026-04-16: The Final Wave F1 contract fix adds explicit `passCount` and `failCount` fields to the representative scenario artifact schema, with successful Task 10 evidence writing `passCount=1` and `failCount=0` while preserving `pass` and `selectedBaseType`.
